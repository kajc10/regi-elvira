# régi ELVIRA

A nostalgia rebuild of [ELVIRA](https://elvira.mav-start.hu/), the Hungarian State
Railways timetable search that MÁV retired in September 2025 — the original look,
running on today's schedules and live delays.

**This is built purely for nostalgia.** The interface is dated on purpose, ELVIRA looked like
this, it worked like this, and I wanted it back. If you want a modern
journey planner, use [MÁVPlusz](https://mavplusz.hu/) — this is not trying to compete
with it.

> It is a one-person hobby rebuild, so expect rough edges — if
> something is wrong or missing, open an issue or a pull request; both are welcome.

**Unofficial.** Not affiliated with MÁV-START Zrt. For anything binding, use the
official site.

## Where everything comes from

| Part | Source |
|---|---|
| Look and layout | The original site, recovered from the Wayback Machine |
| Schedules and delays | The public MÁVPlusz (EMMA) OpenTripPlanner GraphQL API, via a proxy |

## Setup
The solution was designed to be hosted on GitHub pages.

### 1. Proxy

GitHub Pages serves static files only — it runs no code — so the timetable request has
to be made by the visitor's browser. A browser will not read a response from another
site unless that site's reply says it may, and the timetable server sends no such
header, so the request is blocked before the page ever sees it. A small proxy fetches
the data server-side and supplies the missing header. Any host that runs server-side
code would not need a separate proxy for this.

See [`proxy/README.md`](proxy/README.md). It is deployed on
Deno Deploy; a Cloudflare Workers version of the same proxy is also included, and either
can be used depending on what the upstream accepts at the time.

Then put your proxy address at the top of [`assets/js/api.js`](assets/js/api.js):

```js
var API_URL = "https://your-project.deno.net";
```

### 2. Trying it locally

Two commands, two terminals:

```sh
node tools/dev-proxy.mjs        # local stand-in for the proxy, port 8787
python -m http.server 8000      # the page itself
```

then <http://localhost:8000>. Served from localhost, the page picks up the local proxy
by itself, so the search works with real schedules and delays **before** anything is
deployed.

### 3. Publishing on GitHub Pages

Repository → **Settings** → **Pages** → *Deploy from a branch* → `main` / `/ (root)`.
No build step; the repository is served as it stands.

## Refreshing the station lists

The autocomplete reads its names from disk so that typing needs no network. There are
two lists, both generated by the same script and committed to the repo:

| File | What is in it | When it loads |
|---|---|---|
| `data/stations-rail.json` | ~17 000 railway stations from the MÁV feed, Hungarian ones first, international after | always |
| `data/stations-road.json` | ~24 000 Volán, BKK and local coach, bus and trolleybus stops | only after **csak vasúti járat** is cleared |

They are kept apart deliberately. The road list is the larger of the two and its stops
are named `Település, Utca`, so folding it into the default would bury `Szeged-Rókus`
under three hundred Szeged bus stops — and charge every visitor the download for
something ELVIRA never did.

A GitHub Action rebuilds them on the 1st of each month and commits only if MÁV's feed
actually changed, so this normally needs no attention. You can also run it by hand from
the **Actions** tab, or locally:

```sh
node tools/build-stations.mjs
```

The script refuses to write a list that is implausibly short, or that has collapsed
against the one already committed — it exits non-zero and leaves the files untouched, so
a bad answer from upstream fails the run instead of gutting the autocomplete.

## What is missing, and why

- **Fares and tickets** — this page shows timetables only. The "Reduction" dropdown is
  period-correct decoration and is disabled.
- **Delays for future dates** — MÁV only publishes realtime data for trains departing
  soon. Search tomorrow and you get scheduled times.
- **Via** — OpenTripPlanner's `plan` query has no intermediate-point argument, so the
  page fetches both halves of the day and joins them itself. One via station.
- **International journeys** — the station list contains foreign stations, as ELVIRA's
  did, and the timetable even knows their departures. But MÁV's journey planner stops at
  the border: ask it for anything on the far side and it answers `LOCATION_NOT_FOUND`.
  Nothing here can fix that, so the page now says so plainly instead of showing an empty
  table. Search the Hungarian border station instead — Hegyeshalom, Szob, Lőkösháza.

## Layout

- **`index.html`** is the whole page, and has to stay at the repository root — a GitHub
  Pages branch deploy serves either the root or `/docs`, nothing else.
- **`assets/`** is everything the page loads: the recovered stylesheet and images, the
  pictogram font, and the four scripts.
- **`data/`** is generated by `tools/build-stations.mjs`, not edited by hand.
- **`proxy/`** is not served with the site. It is deployed separately — see
  [`proxy/README.md`](proxy/README.md).
- **`tools/`** and **`tests/`** are development only.
- **`.github/workflows/`** holds one job: the monthly station-list refresh.
